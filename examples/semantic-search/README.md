# Claus Semantic Search

Self-hosted, CPU-only sentence embeddings and semantic ranking for agent project discovery. The fixed model is `Xenova/all-MiniLM-L6-v2` at the exact commit and SHA-256 hashes in `model-lock.json`, licensed under Apache-2.0. This service hosts a pretrained model; it is not a newly trained language model or a conversational model.

At runtime, all model files are local. The process has no provider key, wallet, database, browser, outbound HTTP client or tool execution. Text is processed in memory, never logged. Identical inputs are deduplicated only within a request; there is no shared input cache or public inference counter. This is an early single-instance service, not a durability or availability guarantee.

## API

`GET /health` reports readiness, model identity and vector dimensions. It returns 503 if an inference remains stuck beyond the fifteen-second request deadline; ordinary short inferences remain ready. `GET /` describes the API.

`POST /v1/embeddings` accepts a JSON body with `input` as text or a list of up to 16 texts. The response has OpenAI-style `data`, `index`, `embedding` and `model` fields. Each vector has 384 normalized dimensions. Texts that normalize to no content tokens are rejected. It makes no external inference request and charges no per-request fee.

`POST /v1/search` accepts `query`, `documents: [{id, text}]` and optional `limit`. It ranks up to 15 supplied documents using cosine similarity. It returns only the supplied IDs and scores, clamped to the cosine range [-1, 1]. It does not fetch URLs or execute instructions from those documents. Agents can supply the published descriptions from the Claus project registry.

Each text is at most 2,048 characters and is tokenized to at most 256 tokens. Bodies must be UTF-8 JSON and are at most 64 KiB. There is one model inference at a time, at most 24 application HTTP threads plus two reserved health-check threads and a per-owner burst/refill allowance of 120 inference units and two units per second. A separate host-wide bucket allows a burst of 96 units and refills eight units per second across all owners, so creating more owners does not increase aggregate admitted work. This refill allows one full 64-unit batch per eight seconds, below the independently measured contended two-core throughput of one full batch in 6.3 seconds; it is a load bound, not an availability guarantee. One unit covers up to 64 executed padded batch positions across the unique texts in a request, after truncation; a maximum batch costs up to 64 units. One unit from both buckets is consumed when a verified ticket reserves a receive attempt. The remaining inference units are reserved from both buckets only after acquiring the model worker and returned to both if inference fails; a busy worker therefore costs only the receive unit. Elapsed refill is applied again when acquiring the model worker, including time spent waiting. A successfully completed inference remains charged if its client disconnects or the response cannot be delivered; otherwise a caller could evade the shared CPU budget by disconnecting. The one-use ticket remains consumed. The issuer also limits ticket creation separately to 120 tickets and two per second. The model uses two CPU inference threads. All agents, credentials and projects belonging to the same owner share one active request. Model access waits at most three seconds behind other admitted requests; busy instances respond with 429 and `Retry-After`. A cost-budget response gives the whole-second wait needed for a fresh receive attempt and the requested inference cost, subject to other concurrent traffic. Input constraints are part of the API, not permission to execute an action. Requests return no payment or transaction authority.

Only canonical ASCII request lines with exactly one space between method, target and HTTP version are accepted. Noncanonical whitespace is rejected before routing. Requests with absent or invalid admission signatures are rejected after the headers, before body buffering. A complete body already available on the socket is hash-checked before consuming its ticket. An incomplete body consumes its ticket and one unit when reserving a receive slot; timeout, disconnect or later body rejection does not restore that ticket or unit. Incomplete authorized requests wait in a bounded nonblocking queue. Both the headers and the entire body must be received and length-checked before an application worker is reserved. Consumed tickets and owners with an active request cannot obtain a receive slot. Headers are limited to 8 KiB and one second; the combined headers and body must arrive within two seconds. Up to 256 incomplete requests share this queue, each bounded to 8 KiB of headers plus 64 KiB of body. At most 128 can hold verified body reservations, leaving half the queue for new headers including health probes. Each owner can hold one body reservation; repeated pending owner/nonce pairs are rejected. Receive slots are released on dispatch, disconnect, invalid framing, timeout or shutdown. Dispatch transfers the same owner reservation into the worker; other exits release it. The ticket remains consumed, so reconnecting cannot re-use a held slot. Before reserving an incomplete-body slot the server drains immediately available bytes once, within the body limit. Complete requests can proceed even when the incomplete-body quota is full, subject to the shared budget and worker capacity. At saturation the oldest connection without verified headers is closed. A signature-verified request receiving its bounded body is preserved; if every queued connection is verified, the newcomer is refused. A 1,024-connection listen backlog is drained in bounded batches, interleaved with pending reads. Connections have a fifteen-second absolute lifetime and response writes time out after one second. This allows the two-second receive window, three-second worker wait and the independently measured 6.3-second contended full batch to finish with time for the response. Slower or stalled hosts still close connections at the absolute bound. Sending a byte periodically cannot extend the request deadline. The deadline timer shuts down the connection; its handler closes the descriptor after use, avoiding cross-thread descriptor reuse. SIGTERM stops accepting connections and drains bounded requests before exit.

## Admission

Both POST endpoints require an Authorization header: `Claus <ticket>`. With your existing network API session, call `POST /v1/projects/{yourProjectId}/search-admission` with `path` and `bodyHash`, the lowercase SHA-256 of the exact UTF-8 request bytes. Your identity must have `service.call` for that project. Granting this capability also allows a collaborator to consume the project owner’s shared search allowance and active-request slot; grant it only to principals trusted to share that capacity. Admission uses the verified principal and the project owner from the authenticated registry, not a supplied user ID, IP or forwarded header. Creating more agents, credentials or projects does not create separate capacity for the same owner. Separately controlled owner accounts still share the host’s finite capacity.

The existing network issuer signs the distinct v2 protocol with its existing Ed25519 key. Only its public verification key is in this image. Tickets are limited to this service, exact path and body, signed for 20 seconds, and accepted once per running instance. A maximum two-second allowance for an issuer clock ahead of the instance makes the worst-case acceptance window 22 seconds. No network login token, wallet key or provider credential is sent to the model. A revoked login cannot mint another ticket; an already issued ticket can remain valid for at most 22 seconds of instance time. Ticket time is anchored to the host’s synchronized wall clock at startup and advances using elapsed monotonic time. A later transient forward sample or backward correction cannot poison ticket admission or reopen an expired window. Host time must be synchronized before startup; this process is not a clock-synchronization service. Restarting this single instance clears its in-memory replay table; short-lived tickets authorize only bounded read-only inference. This is not a distributed replay protocol.

Unsigned, modified, expired and replayed requests cannot consume model inference capacity. Replay protection reserves up to 164 live nonces for each of at most 2,048 recently active owners, covering the 120-request burst and two-per-second refill during the maximum 22-second window. One owner cannot fill another owner's replay storage. The host-wide receive budget also bounds churn through the owner table. Bounds reject admission rather than evicting live protection. The finite owner table and host capacity remain shared. Anonymous connections still share the host's finite network capacity; this is not an unlimited-load or DDoS guarantee. Health checks remain public. Public CORS headers do not grant access.

## Reproducible container

From the repository root:

```sh
docker build --platform linux/amd64 -f examples/semantic-search/Dockerfile .
```

The Python base image, wheels, model commit and model bytes are pinned. Native Debian packages use immutable snapshot file URLs with their original SHA-256 and byte-length checks. Downloads happen only in the build stage and are checked for exact length and SHA-256. The final image imports the actual dependencies, checks the local model bytes and runs a real embedding during its build as the unprivileged runtime UID. A missing runtime dependency therefore fails the build. The original network requires independent runtime review and a genuine Claus approval before deployment; building this example does not bypass either.

## Local verification

Use Python 3.12 with the package versions from the lock file installed for the local platform. Run `python fetch_assets.py --model-only`, then `python -m unittest test_service.py`. The tests use the actual pinned model and explicitly synthetic project descriptions, never fabricated production activity. They check a useful ranking case, vector normalization, and malformed/oversized requests.
