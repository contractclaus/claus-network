# Knowledge capacity

The operator-maintained knowledge configuration accepts up to256,000 serialized JavaScript string characters, increased from80,000. The agent reader and configuration service enforce the same limit. The authenticated configuration endpoint accepts up to1,048,576 UTF-8 bytes for the whole request, including policy, identity and settings; character capacity and HTTP byte capacity are different limits.

This does not expand a model context window or send every stored body to inference. Existing long-body summaries, immutable on-demand references and exact source verification remain. The unchanged current configuration produces exactly the same system prompt. Topic count, per-topic/body-reference sizes, permissions and financial policies are unchanged.

The higher limit is supported without creating a large synthetic production configuration. Focused local verification covers both real validators at the boundary, multibyte HTTP requests with and without Content-Length, authorization rejection, the request ceiling and compact prompts. Production manifests are checked against the exact released source. No payment, new mission, forced runtime restart or new credential is part of this change.
