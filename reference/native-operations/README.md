# Native operating tools

Exact source excerpts from the deployed Claus host. These files import the host’s existing stores, configuration and fixed service adapters; they are not standalone client libraries. The manifest binds each excerpt to its deployed source.

The release controller supports scoped source changes. Website changes retain their reviewed path. Native/API server-source editing is currently disabled pending separation from privileged signing and database access; the model must read current scope rights before proposing an edit. A separate review, immutable source snapshot, unaliased build and source/health readback precede activation. Original review and deployment identities survive interrupted requests. Explicit hosting rejections retain the original source and review and stop without another deployment; uncertain outcomes keep reconciling the original intent. A rollback restores code only; this path cannot modify database schemas, release controllers, authentication or financial code. This is constrained production editing, not a security sandbox for arbitrary JavaScript.

The native host uses a fixed-purpose external Jobs custodian and no longer receives its private key. Original accounting was copied exactly to the signer database; the old native ledger is read-only. Existing bounded work payments remain. This does not yet isolate every publisher or database privilege. The dedicated Jobs wallet can also sponsor the gas for an already-due public ETH/CLAUS escrow settlement. It calls only the fixed escrow’s settleExpired method with zero value, retaining the existing cumulative gas allowance. It cannot choose a recipient or transfer wallet principal. Escrow rules determine the original parties’ credits; settlement is not their withdrawal. Existing paid-work budgets are unchanged.

Operational documentation reviews include a timestamped, allowlisted read of the fixed Jobs custodian policy. Private balances, job data and credentials are excluded. A service-policy observation is not an executed payment or approval for new financial rights. The original documentation review rejected for missing evidence remains recorded; the owner adopted the verified text separately.

Long knowledge records are retrieved by topic when needed. Current owner rules remain in every operating prompt. Inbox compaction retains complete admitted conversations and their freshness bindings, leaving other messages pending. Operational tools are exposed in the normal model loop and excluded from private Club execution.

This release does not grant general wallet signing, token-core upgrades, unbounded spending or unrestricted server access. A separate fixed-purpose trade-program lane supports exact independent review and bounded installation through the mandatory treasury adapter. Its code is published in ../trade-programs. No new program is implied by installing these tools. Full operational handover remains incomplete.

Runtime knowledge now includes a dated view of the actual model schemas, local execution gates and per-scope publisher controls. Missing observations remain unknown; an exposed schema alone is not permission, remote availability or a successful action. The view contains no keys, balances or private jobs.

Private operating receipts may support an internal work assessment. Publishing that assessment still requires public evidence. Nested service errors, unknown effects and incomplete transaction responses do not become successful work receipts. Existing effects and financial reservations are unchanged.
