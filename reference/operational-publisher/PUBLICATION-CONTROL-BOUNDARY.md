# Publication authority outside the Native runtime

R28 moves active-version and runner-pin writes out of Native. The fixed publisher has a separate, narrow database role. Native can read these controls but cannot insert, update or delete them. The publisher cannot toggle the owner's enabled flags. The separate local operator remains responsible for those flags and infrastructure rollouts.

Surface and operational activation recheck the original independent review, original provider journal, actual hosted source and health, then compare the unchanged authority and release inside the committing transaction. Active version, fallback and append-only audit commit together. Unknown outcomes resume the original receipt; they do not create replacement deployments or purchases. Native's legacy pin/enable routes return 410. The existing code-edit scopes remain unchanged.

The surface health observer now runs inside the fixed publisher. Its fallback uses the existing protected target and verifies the immutable original files and health. A caller cannot supply a URL or choose an unreviewed fallback. Native operational adoption only pins an actually published, currently enabled deployment recorded by the fixed authority path, after the prior builder lease drains.

Database triggers protect admitted source, changes, original identity and baseline from later rewriting. Progress, verdict references and provider receipts can still advance without replacing original work. This does not make a Native-written verdict authoritative; the independent payer evidence remains required.

No general Node/SQL/signing or new financial rights are delegated. Native/API still have other work, identity and client boundaries to separate before broad source control. This release does not complete all five handover packages, prove external collaboration or autonomous funding, nor perform a production database cutover.
